## 1. すぐ使う場合

1. 記入用サンプル security-sample.json をコピーする。単一選択と複数選択の計2問が入っている。
2. questionSetId、title、categories、questionsを編集し、settings.questionCountを在庫以内にする。
3. 管理画面の「設問プール／組み立て」で読み込み、配分・正解を確認して保存する。

仕様書・サンプルは管理画面のリンクからも取得できる。ファイルの読込・編集だけではGitHubは変更されない。「GitHubに保存」で反映し、自動デプロイ完了後に受験ページを再読み込みする。

## 2. 検定名・Set ID・保存先ID

| 名前 | 場所 | 用途 |
|---|---|---|
| 検定名 | title | 画面・結果に出す名前 |
| Set ID（JSON内） | questionSetId | 同じセットかを判定する内部名 |
| 保存先ID | sets/<保存先ID>.jsonのファイル名部分 | GitHubで保存・取得・切替するファイルを指定 |
| 問題ID | questions[].id | 1セット内の問題を識別 |

- 同じSet IDなら、ファイル名やversionが異なっても同じセットとして扱う。
- titleが同じでもSet IDが異なれば別セット。
- Set IDは前後の空白なし、空でない文字列、64文字以内。比較は大文字小文字を含む完全一致。
- 新規には半角英数字・ハイフン・アンダースコアを推奨。例：it-security-2026-10。
- 保存先IDは半角英数字・ハイフン・アンダースコアの1〜64文字。APIは不正値を拒否する。プールの保存先入力は使える文字へ整え、確認画面に整えた保存先を表示する。
- 保存先名を変更してもJSON内のSet IDを自動変更しない。新しい独立セットならSet IDも明示的に変更する。
- APIのsetIdとactive-set.jsonのactiveSetIdは保存先ID。questionSetIdと混同しない。

## 3. 標準形式

受験画面に公開するJSONは、セット全体を表すオブジェクトにする。UTF-8、二重引用符を使い、コメントや末尾の余分なカンマを入れない。数値・真偽値を文字列にしない。

```json
{
  "questionSetId": "sample-basic",
  "version": "1.0.0",
  "title": "情報管理チェック",
  "theme": "情報管理",
  "settings": {
    "questionCount": 1,
    "passingScore": 70,
    "randomizeQuestions": false,
    "randomizeChoices": true,
    "categoryDistributionMode": "weighted",
    "categoryDistribution": [
      { "categoryId": "C-003", "weight": 1, "priority": 1 }
    ]
  },
  "categories": [
    { "id": "C-003", "name": "情報管理" }
  ],
  "questions": [
    {
      "id": "Q001",
      "category": "情報管理",
      "difficulty": "basic",
      "type": "single",
      "question": "社内情報を外部サービスへ入力する前に、何を確認しますか。",
      "choices": ["社内の利用ルールを確認する", "確認せずに入力する"],
      "answer": [0],
      "explanation": "入力してよい情報か、社内ルールに従って確認します。",
      "tags": ["情報管理"]
    }
  ]
}
```

### プール取込で受け付ける別形式

- 設問配列だけのJSON：questionsの中身だけを配列として保存したもの。
- 生成案の包み：questionSetDraftの中に上記のセットオブジェクトを持つもの。

これらは取込用で、受験画面の公開用JSONへそのまま配置する形式ではない。IDなしの場合は取込画面でSet IDを入力する。1回の取込内の設問検査と追加・置き換えの選択が終わるまで、既存プールは変更しない。

## 4. セット全体の項目

「必須」はGitHub保存APIの共通検査で要求する主要項目。「推奨」は作成時に記入したい情報。

| 項目 | 型 | 必須・用途 |
|---|---|---|
| questionSetId | 文字列 | 必須。Set ID。IDなし取込では入力後に付与 |
| version | 文字列 | 推奨。例1.0.3。生成案はdraftも使う。内容の版で、アプリ版・文書版とは別 |
| title | 文字列 | 任意。他テーマでは推奨。表示時40文字まで |
| theme | 文字列 | 任意。他テーマでは推奨。生成・コメントの観点。40文字を基準に整理 |
| description | 文字列 | 任意。トップ説明。表示時300文字まで |
| footerNote | 文字列 | 任意。トップ下部の注記。表示時300文字まで |
| resultNote | 文字列 | 任意。コピー・メール本文末尾。表示時200文字まで |
| perfectMessage | 文字列 | 任意。全問正解の復習文。表示時200文字まで |
| rankComments | オブジェクト | 任意。S/A/B/C/Dをキーにしたコメント。各表示時120文字まで |
| updatedAt | 文字列 | 推奨。UTCのISO日時。例2026-10-18T06:00:00.000Z。管理画面は日本時間表示 |
| settings | オブジェクト | 必須。出題設定 |
| categories | オブジェクトの配列 | 必須。1カテゴリ以上。ID・名前をそれぞれ重複させない |
| questions | オブジェクトの配列 | 必須。1問以上。在庫の配列 |
| locked | 真偽値 | 古いデータの互換項目。操作制限には使わない |
| generatedBy | 文字列 | 任意の生成元情報。出題・採点には使わない。プール書き出しでは保持しない |

文字数は表示用の値を整える際の上限であり、保存APIがその文字数で拒否する上限ではない。titleもthemeもなければAIリテラシー向けの既定文、片方だけあれば中立の既定文になる。別テーマでは両方を明示する。

未知の追加項目は、編集後も保持される保証がない。schemaVersionは定義しておらず、versionを変えても形式の移行処理が走るわけではない。

## 5. settings

| 項目 | 型 | ルール・意味 |
|---|---|---|
| questionCount | 整数 | 保存時必須。1以上、questionsの件数以下。管理画面・AI生成の入力は1〜100 |
| passingScore | 整数 | 保存時必須。0〜100。合否だけに使用。ランク境界は固定 |
| difficulty | 文字列 | basic / standard / advancedを推奨。AI生成の指示。受験時の難易度絞込ではない |
| randomizeQuestions | 真偽値 | 任意。trueでカテゴリ内抽出と全体の出題順をランダム化 |
| randomizeChoices | 真偽値 | 任意。trueで選択肢を混ぜ、正解番号も対応させる |
| categoryDistributionMode | 文字列 | weightedを記入。現在はこの文字列で計算方式を切り替えない |
| categoryDistribution | 配列 | 任意。次表。省略・全重み0ではカテゴリ定義のweight等を基にする |
| showExplanationAfterAnswer | 真偽値 | 古い互換項目。回答直後の解説表示の切替には使わない |

在庫そのものを100問に制限する意味ではない。出題数を在庫より多くして公開することはできない。JSON内のquestionCount自体の共通検査は在庫までで、管理画面・生成の入力上限とは別。

### 配分の各要素

| 項目 | 型 | ルール |
|---|---|---|
| categoryId | 文字列 | categories[].idと一致。重複不可 |
| weight | 整数 | 0以上。出題割合の比率 |
| priority | 整数 | 1以上。小さい数字を優先 |

重み3:1、20問なら15問:5問。端数は小数部分が大きい順、同点なら優先度などで整数にする。AI生成と受験は同じ配分関数を使う。

カテゴリ別在庫が足りなければ、受験時は他のカテゴリから補充する。プールで在庫が出題数を超えるとランダム出題が自動で有効になる。ランクはS=90/A=80/B=70/C=60以上、それ未満D。複数選択に部分点はない。

## 6. categories

| 項目 | 型 | ルール |
|---|---|---|
| id | 文字列 | 空でない、一意のカテゴリID |
| name | 文字列 | 空でない、一意のカテゴリ名 |
| description | 文字列 | 任意。現在の受験画面では未使用 |
| weight | 数値 | 任意。明示配分がない場合の比率。省略・0は1として扱う |

設問のcategoryには**name**を書く。配分のcategoryIdには**id**を書く。独自カテゴリでも同じ。

従来の定義はC-001=基本理解、C-002=指示の出し方、C-003=情報管理、C-004=セキュリティ、C-005=法務・倫理、C-006=業務活用、C-007=最新トレンド。

1.2.0のAI生成は現在のセットのカテゴリ・テーマを使い、X-001等の独自カテゴリにも対応する。現在のセット情報がない場合は従来の7カテゴリを使う。生成入力のカテゴリは50個まで。存在しないカテゴリの生成結果は採用しない。

プールは既知のC系コード表記を名称へ整理するが、独自IDから名称を自動解決する前提にはしない。設問にはカテゴリ名を書く。

## 7. questions

| 項目 | 型 | ルール・用途 |
|---|---|---|
| id | 文字列 | 保存時必須。セット内で重複不可。例Q001 |
| category | 文字列 | 空でなく、categories[].nameと一致 |
| difficulty | 文字列 | basic / standard / advancedを推奨。不明値は取込時standardへ整理 |
| type | 文字列 | single / multiple |
| question | 文字列 | 空でない問題文 |
| choices | 文字列の配列 | 空でない選択肢2個以上。4個は例で固定ではない |
| answer | 整数の配列 | 0始まりで範囲内、空・重複不可。singleは1個 |
| explanation | 文字列 | 復習用の解説。簡潔な文を推奨 |
| tags | 文字列の配列 | 任意。出題抽出には未使用 |

answer [0] は1番目、[1]は2番目、[0,2]は1番目と3番目。multipleは2個以上を推奨するが、互換性のため検査では1個も受け付ける。順序を問わず正解集合と完全一致したときだけ正解。

設問配列の取込では、問題IDは後で振り直せるため省略できる。type省略はsingle、category省略は未分類として取り込む。answerが単一の数値の旧形式も配列へ変換する。新規では表の型で作成する。

取込時・保存時に空の問題文、選択肢不足、範囲外や欠落した正解を拒否する。以前の「正解がなければ先頭選択肢にする」補完は行わない。編集で正解をすべて外した場合も保存前検査で止める。

## 8. 公開・管理用ファイル

| ファイル | 内容 |
|---|---|
| public/data/sets/<保存先ID>.json | 保管用の標準セット |
| public/data/current-question-set.json | 受験者が読む公開用コピー |
| public/data/active-set.json | 使用中の保存先IDと更新日時 |
| public/data/set-status.json | 無効化した保存先IDの一覧と更新日時 |

active-set.jsonの例：

```json
{
  "activeSetId": "it-security-2026-10",
  "updatedAt": "2026-10-18T06:27:05.756Z"
}
```

set-status.jsonの例：

```json
{
  "disabledSetIds": ["unused-sample"],
  "updatedAt": "2026-10-18T08:00:00.000Z"
}
```

- disabledSetIdsはSet IDではなく**保存先ID**の配列。ファイルがなければ全セットが有効として扱う。
- 無効セットは一覧に残り、読込・編集・再有効化が可能。使用するセットへの切替は拒否する。
- 使用中セットの無効化・削除は画面とサーバーで拒否する。別のセットへ切り替えてから操作する。
- 削除は保管ファイルを消し、無効一覧からも外す。アプリ内ごみ箱はない。復元はGitHubの履歴から行う。編集中のプールを自動削除しない。
- 設定保存・生成案採用では公開用と使用中の保管用を同時に更新する。使用中の保管セットをプールから保存した場合も公開用に同時反映する。
- 切替・保存の関連ファイルは1つのGitコミットで反映する。読込後に他の更新があれば409で拒否し、上書きしない。

APIのlist/getはrevisionを返す。変更要求にはexpectedRevisionを付ける。save_currentにはexpectedActiveSetIdも必要。通信失敗時は自動再送せず、最新状態を確認する。競合時は未保存のJSONをダウンロードしてから最新のセットを読み込み直す。

## 9. Set IDを使った取込と画面表示

- 同じSet IDがプールに存在すると「追加」「同じセットだけ置き換え」「キャンセル」を選ぶ。
- 追加は既存を残し、取込分を追加する。同じ文を自動で削除する意味ではない。
- 置き換えは、そのSet ID由来の設問と手編集を新しい設問へ入れ替える。他のセットの問題・手編集・採用選択を保持する。
- IDがなければ、保存済みのJSON内Set ID一覧を参照して入力する。選択は入力の補助で、保存済みファイルを自動変更しない。
- 複数ファイルは選択順に処理し、同じIDが再登場するたびに選択する。取消はそのファイルの取込を取り消す。
- JSONの中にあるIDを、版やファイル名から勝手に推定しない。

管理画面は、Set ID（JSON内）、保存先ID、保存ファイル、版・出題数・在庫・状態を分けて表示する。JSON内IDがなければ未設定と表示する。Set IDのコピーボタンと、IDなし取込時の既存ID選択を備える。

読込元IDは各設問の内部状態originSetIdで保持する。書き出しJSONにはこの内部状態を含めない。複数セットを統合して1つのJSONにした後に再読込した場合は、統合後のSet ID由来として扱う。

## 10. 編集・保存で引き継ぐもの

- ファイルの最初の取込ではSet ID、版、名称文言、出題数・合格ライン・ランダム設定、カテゴリと配分を取り込む。
- 他セットの追加では、編集中セットのメタ情報を全面上書きしない。
- 同じ出力Set IDの置き換えでは、新しい版・名称・カテゴリ情報を取り込む。手入力した出題数等は画面で確認する。
- プール書き出しは採用設問から作り直す。問題IDはQ001から再採番。カテゴリIDは対応可能な元定義を優先し、衝突時に別IDを振る。
- 配分は同じ出力Set IDに対する管理画面設定を優先し、ほかは取込元の配分と在庫数を基にする。
- 未知の項目、categories[].description、元のlockedやgeneratedBy等を全面的に保持する形式ではない。
- 保存先IDとSet IDが違う既存セットも、プール保存時にSet IDを保存先名へ強制変更しない。

## 11. 作成・受入確認

JSONを解析できること、Set ID・問題ID・カテゴリの対応、出題数と在庫、選択肢と正解番号を確認する。本文・解説・正解が内容として正しいかは人が確認する。

自動確認はtests/scoring.test.js、set-management.test.js、pool-import.test.js、generate-questions.test.js。ブラウザ統合確認はscripts/browser-smoke.cjsを使う。ブラウザ確認ではGitHub・外部AIを代用し、本番の保存データは変更しない。PC Chromiumと390pxのWebKitを確認し、実機スマートフォン・メールアプリの検証と区別する。

実装・公開の証拠と残る確認事項はdocs/release-1.2.0.mdに記録する。今回の改修では、JSON本体へenabled・disabled等を付けても無効化には使わず、set-status.jsonで管理する。
